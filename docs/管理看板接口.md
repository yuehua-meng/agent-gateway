# 管理看板接口

用于维护前端或内部管理脚本。模型调用入口和项目 Key 接入见 [项目 README](../README.md)。以下接口均在 [gateway/main.py](../gateway/main.py) 实现。

## 鉴权与数据范围

请求头使用 `Authorization: Bearer <GATEWAY_ADMIN_KEY>`，不能使用项目 Key。管理员能查看全部项目，因此这些接口不应直接提供给普通业务调用方。返回数据不包含供应商 Key、Prompt、图片或模型回复正文。

PowerShell 只读调用示例（假设管理员已在当前进程设置该环境变量；命令不会自动读取 `.env`）：

```powershell
$gatewayHeaders = @{ Authorization = "Bearer $env:GATEWAY_ADMIN_KEY" }
Invoke-RestMethod -Uri 'http://127.0.0.1:8020/admin/status' -Headers $gatewayHeaders
Invoke-RestMethod -Uri 'http://127.0.0.1:8020/admin/observe/analytics?days=7' -Headers $gatewayHeaders
```

## 接口清单

| 方法与路径 | 用途 | 主要返回 |
|---|---|---|
| `GET /admin/status` | 当前配置、运行容量与原有状态 | `mode`、`active_requests`、`capacity`、`projects`、`deployments`、`daily`、`recent`、`costs`、`unknown`、`blocks` |
| `GET /admin/observe/analytics` | 当前筛选范围的完整统计 | `requests`、各状态数量、`success_rate`、`p95_ms`、`usage`、`retries`、`trend`、`groups`、`recent`、`as_of` |
| `GET /admin/observe/requests` | 请求列表 | `total`、`items`、`offset`、`limit` |
| `GET /admin/observe/requests/{operation_id}` | 单请求与上游尝试 | `operation`、按开始时间排序的 `attempts` |
| `POST /admin/reset-block` | 管理员主动清除停用记录 | `status`、`scope` |

`/admin/status` 的 `recent`、`unknown` 各最多 50 条，不能用这些数组的长度计算整个周期总量。统计应使用 `analytics`。`active_requests` 包含引擎处理的任务（含图片等待）；具体执行数看 `capacity`。

`capacity` 示例（空闲状态）：

```json
{
  "text_active": 0,
  "text_limit": 200,
  "image_active": 0,
  "image_limit": 10,
  "image_waiting": 0,
  "image_queue_limit": 6
}
```

## 筛选与分页

`analytics` 和 `requests` 都支持：

| 参数 | 默认 | 说明 |
|---|---|---|
| `days` | 7 | 整数 1–30；滚动时间窗口，以操作创建时间筛选 |
| `project` | 空 | 精确项目标识，最长 200 字符；空表示全部 |
| `alias` | 空 | 精确逻辑模型别名，最长 200 字符；空表示全部 |

`requests` 额外支持：

| 参数 | 默认 | 说明 |
|---|---|---|
| `state` | 空 | `succeeded`、`failed`、`running`、`unknown` 或空 |
| `query` | 空 | 最长 200 字符；不区分大小写，子串匹配请求 ID、任务 ID、项目或别名 |
| `offset` | 0 | 非负整数，跳过的记录数 |
| `limit` | 20 | 每页 1–100 条 |

列表按创建时间降序。详情按操作 ID 查询，不受列表筛选或时间窗口约束，但历史尝试可能已清理。不存在的项目/别名筛选返回空结果，参数越界返回 422。

## 统计语义

- 成功率 = 成功 /（成功 + 失败）；运行中、待核对不进入分母。无已完成请求时为 null。
- P95 对成功和失败操作耗时采用最近秩法计算，单位毫秒，包含排队与重试；无样本时为 null。
- 成功结果缓存过期的操作在观测接口中仍为 `succeeded`，同时 `result_expired=true`；项目结果查询仍返回过期错误。
- `retries` 是各操作额外尝试数之和，包含切换；`usage.calls` 是上游尝试数。
- `trend` 按北京时间分日，补齐无请求日期；首尾日期可能不足一天。
- `groups` 包含 `project`、`model`、`deployment` 三种维度，按尝试数降序。`model` 是发生时记录的实际模型，`alias` 筛选是逻辑模型。
- `analytics.recent` 最多 8 个操作，完整列表使用 `requests`。Token 和费用字段见 [统计与计费](Token统计与计费.md)。

`POST /admin/reset-block` 的 JSON 为 `{"scope":"从 blocks 中取得的实际 scope"}`。仅在确认充值、换 Key 或权限修复后使用；它只清除停用状态并写审计记录，不主动验证上游，不保证恢复后一定成功。

常见错误：未提供有效 Bearer 格式为 401；管理凭据不匹配为 403；操作/停用项不存在为 404；查询参数无效为 422；SQLite 不可用可能返回 503。框架参数错误使用 `detail`，业务错误使用 `error`，调用方需兼容两种错误结构。
