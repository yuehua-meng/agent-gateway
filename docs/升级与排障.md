# 升级与排障

本文补充新增看板、Token 字段和共享并发功能的运维方法。以下命令均在网关根目录执行。完整安装方法见 [README](../README.md)。

## 升级步骤

1. 查看当前执行与等待数，尽量在空闲时停止旧进程。保持单实例，不通过增加 worker 绕过进程锁。
2. 备份数据库；备份名必须是未存在的新文件：

   ```powershell
   .\.venv\Scripts\python.exe manage.py backup backups/gateway-before-update-20261003.db
   ```

3. 单独保存 `config.json` 和 `.env`。数据库备份不包含配置与凭据，备份库本身可能包含幂等查询所需的模型结果。
4. 核对配置的 `text_concurrency=200`、`image_concurrency=10`、`image_queue_limit=6`、`image_queue_timeout=60`。旧文件有显式值时，默认值不会覆盖它；不要用示例文件覆盖已有项目和厂商配置。
5. 使用 `start.cmd` 或 `.\.venv\Scripts\python.exe run.py` 启动。启动会自动增加缺少的数据库列和索引，无需手工删库或回填。
6. 打开看板重新登录，查看容量是否为 200 / 10 / 6；调用 `/health` 验证存活，调用 `/admin/status` 验证配置。`/health` 成功不代表供应商接口或配额已验证。

老记录新增 Token 明细保持未知；既有停用记录不会因为重启自动恢复。未完成操作在重启时标记待核对，不自动重发付费请求。

## 常见问题

| 现象 | 检查与处理 |
|---|---|
| 看板仍显示旧上限 | 检查实际运行目录和 `config.json`，停止旧进程后重启；只刷新网页不会重载后端配置 |
| 文本返回 `GATEWAY_BUSY` | 查看是否已达到文本全局上限；稍后有限重试，检查慢上游、异常循环或批量任务 |
| 图片返回 `GATEWAY_BUSY` | 查看执行与等待数、请求总时限；若未发送上游，可用原幂等键和相同内容重试 |
| `PROJECT_DAILY_LIMIT` | 项目每日上游尝试次数已用完；这与并发上限不同，重试和切换也计次数 |
| `UPSTREAM_RATE_LIMITED` | 是厂商限流，调高网关并发不会增加厂商额度；查看候选配额组冷却及厂商账户配额 |
| 缓存/推理 Token 显示未知 | 可能是历史记录、供应商没返回或字段格式未适配；不是证明没有缓存或推理用量 |
| Token 有值但费用未知 | 检查候选的输入/输出单价、必要 usage 是否齐全；不会把未计价当免费 |
| 估算费用与账单不同 | 当前未适配缓存折扣、分档和所有供应商计价规则；账单以厂商为准 |
| 图片显示 `RESULT_UNKNOWN` | 请求可能已受理；先查厂商任务和账单，不能因为客户端超时就换幂等键自动重发 |
| 启动提示目录已被使用 | 检查已有网关进程；不要通过删除锁文件或启动更多 worker 强行绕过 |
| 返回 `STORAGE_UNAVAILABLE` | 检查磁盘空间、数据库目录写权限及服务日志；修复前不要删除记录或绕过去重保护 |

## 备份与恢复

默认每天在线备份数据库到 `data/backups`，保留最近 7 份；另保留一份到独立存储。成功响应内容通常保留 7 天，普通尝试约 30 天，未知费用按原策略保留。

恢复时先停止服务并保存现有数据，将选定备份放入新的数据目录并命名为 `gateway.db`，再使用该目录恢复。不要将备份主库与旧 `-wal`、`-shm` 文件混用。恢复后首次启动仍执行未完成操作恢复逻辑；不要在运行中的实例旁并行启动同一库。

```powershell
.\.venv\Scripts\python.exe -m pytest --tb=short -p no:cacheprovider
node --check web/app.js
```

并发与 Token 新功能的最近一轮完整回归为 65 项通过，详见 [验收记录](../验收记录.md)。测试使用模拟上游；200 文本 + 10 图片 + 6 等待验证的是限制和释放正确性，并非真实供应商性能压测。

`smoke.py` 在演示模式可用于基础调用检查；真实模式带 `--live` 会产生实际模型调用，只在明确需要时运行。本轮文档整理不需要调用模型，也不更改运行配置。
