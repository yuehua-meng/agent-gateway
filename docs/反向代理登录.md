# 反向代理登录：看板免重复输入 Key

腾讯云看板通过 Caddy 的用户名/密码保护。浏览器完成这一次登录后，Caddy 为转发到网关管理接口的请求附上内部 Bearer 凭据，看板自动连接，不再要求输入 `GATEWAY_ADMIN_KEY`。

网关管理接口仍校验 Bearer；模型调用接口仍校验项目 Key。管理员 Key 只存在于服务器，不写进 HTML、JS、接口响应或浏览器存储。

## Caddy 配置原则

1. `/gateway/`、静态资源和 **全部 `/gateway/admin/*` 路径**必须受前置密码保护；移除旧的 admin/static 认证豁免，其他站点的例外规则保持不变。
2. `/gateway/admin/*` **只剥去 `/gateway`，保留 `/admin`** 后代理到 `gateway:8020`，覆盖上游 Authorization 为 `Bearer <服务器的 GATEWAY_ADMIN_KEY>`。
3. 注入只限管理接口；`/gateway/v1/*` 继续禁止公网访问。Caddy 未验证密码的请求不得进入注入规则。
4. 可通过 Caddy 环境变量提供 Key；如写入服务器私有 Caddyfile，该文件必须限制读取权限并排除 Git。更换网关 Key 时同步更新并 reload Caddy。
5. 保留网关只接入 Docker 内网的部署方式，不为免登录而直接开放管理端口。

不能只删除前端输入框、公开管理接口，或把 Key 硬编码到 JS。前端自动探测 `admin/status`，成功后进入看板，刷新无需再次输入 Key。代理模式不显示“断开”按钮，该按钮不能退出浏览器前置认证。

本地直接访问网关、没有前置代理时，自动探测失败后仍显示管理员连接表单，便于独立开发使用。自动模式请求不设置 Authorization，从而不会覆盖浏览器缓存的 Basic 登录凭据；手动模式才设置 Bearer。

## 验证

- 未登录访问页面和管理接口返回 401，不能仅凭伪造转发头获得访问。
- 正确前置密码可打开总览、调用列表、Token 页面并刷新，管理员连接表单保持隐藏。
- 浏览器收到的 HTML/JS 和管理接口响应不包含内部 Key。
- 无代理的本地页面继续要求管理员 Key，项目 Key 不能登录。

实现：[app.js](../web/app.js) 的 `initialize`、`api` 和 `refresh`；[index.html](../web/index.html) 默认隐藏表单以避免自动连接时闪现。


## 管理路由示例与排障

```caddyfile
handle /gateway/admin/* {
    uri strip_prefix /gateway
    reverse_proxy gateway:8020 {
        header_up Authorization "Bearer {env.GATEWAY_ADMIN_KEY}"
    }
}
```

该规则位于受密码保护的站点内；环境变量由服务器配置。不要使用 `handle_path /gateway/admin/*`，它会把 `/gateway/admin` 整段删除，导致 `/gateway/admin/status` 错转成 `/status` 并返回 404。正确上游路径是 `/admin/status`，查询参数保留。

部署页面 `/gateway/` 自动连接失败时仅显示连接错误和刷新入口，不退回管理员 Key 表单；本地独立访问仍保留手动模式。
